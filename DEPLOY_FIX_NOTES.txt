SALES CRM MANAGEMENT - PRODUCTION HARDENING
===============================================

This package is the consolidated deployment version.

MAIN FIXES
----------
1. Fixed the original import-chain failures by keeping all CRM schemas centralized
   in backend/models/crm.py.
2. All production routers are imported explicitly; no feature is silently skipped.
3. Added /api/* compatibility aliases for the existing frontend and API tests.
4. Kept clean public Swagger paths such as /customers and /pipeline.
5. Added /api and /api/health endpoints.
6. Production root now serves the React CRM application instead of raw JSON.
7. Added React SPA fallback so /customers, /pipeline, /quotations, etc. survive
   browser refreshes.
8. Added a premium 404 page.
9. Frontend API client supports VITE_API_URL and robust API/network errors.
10. Authentication remains httpOnly-cookie based.
11. Cookie Secure behavior is configurable through COOKIE_SECURE.
12. Session records receive a 7-day MongoDB TTL index.
13. Added MongoDB connection timeouts, pool settings, and production indexes.
14. Added Super Admin RBAC protection to users/audit/export administration APIs.
15. Added root Dockerfile using a Node frontend build stage and Python/FastAPI runtime.
16. Added railway.toml with Docker build, health check, and restart policy.
17. Added .dockerignore and backend/.env.example.
18. No real credentials are included.

DEPLOYMENT
----------
Push the project root (including Dockerfile and railway.toml) to the GitHub
repository connected to Railway. Do not upload node_modules or any .env file.
Railway builds the frontend and backend into one service.


Railway build fix v2: removed the apt-get/curl runtime layer because the build was being killed during [runtime 3/7]. The container only needs Python/uvicorn and does not require curl.
